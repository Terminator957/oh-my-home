## 一、诊断：为什么原来的中文没生效

你机器上已经装过一次语言包（7 月 4 日版，针对 Claude Desktop 1.18286.0.0），但 Claude 今天更新到了 **1.24012.9**。查出三个层次的问题：

### 1. 致命问题：新版多了一个必需文件，旧语言包没有

新版前端加载语言的代码（`ion-dist/assets/v1/index-C9LAU4f-.js`）是这样的：

```js
const [s, a, n] = await Promise.all([
  fetch(`/i18n/${e}.json`),
  fetch(`/i18n/dynamic/${e}.json`),
  t ? fetch(`/i18n/${e}.overrides.json`).catch(() => null) : Promise.resolve(null)
]);
if (!s.ok) throw new Error(`Failed to fetch public i18n messages: ${s.status}`);
if (!a.ok) throw new Error(`Failed to fetch dynamic i18n messages: ${a.status}`);
```

`/i18n/dynamic/<语言>.json` 是**硬性必需**的，取不到就直接抛错，整份中文加载失败并回落英文。

新版把这批文案（模型选择器、思考强度、网络搜索开关等 49 条）从 `i18n/statsig/` **移到了 `i18n/dynamic/`**。旧语言包只装了 `statsig/zh-CN.json`，`dynamic/zh-CN.json` 不存在 → 404 → 中文整体失效。

### 2. 覆盖率问题：新版文案大量增加

| 文件 | 1.18286 条目 | 1.24012.9 条目 | 旧包能覆盖 | 缺口 |
|---|---|---|---|---|
| `ion-dist/i18n/zh-CN.json` | 18363 | **19913** | 15924 | **3989 条无译文** |
| `resources/zh-CN.json`（菜单/托盘） | 435 | **473** | 421 | **52 条无译文** |
| `i18n/dynamic/zh-CN.json` | —（当时在 statsig） | **49** | 23 | **26 条无译文** |

另有 **2439 条**旧 key 已被新版废弃，属于无用残留。

### 3. 质量问题：旧译文存在成片错位

key 的生成规则是 `base64(sha512(英文原文))[:10]`（内容寻址，已用 16972/18363 条实测验证），所以版本升级**不会**导致错位——错位是旧包自身翻译批次的缺陷：

- **成片的 off-by-one 错位**：某条 key 装的是相邻条目的译文。集中在 key 以 `q` 开头的区段，例如 `Try asking...` 的译文变成「此规则允许的请求将落到优先级较低的规则或默认被拒绝。此操作无法撤销。」，`Disconnect` 变成「让 Claude 使用第三方服务显示地图、图片和其他视觉内容。」
- **ICU 撇号陷阱**：`名为'{name}'的连接器已存在` —— 半角单引号紧贴 `{` 会被 ICU 当成转义符，占位符失效，界面上会直接显示 `{name}` 字样。
- **富文本标签重复**：`<span1>正在以</span1> <span2>{email}</span2><span1>身份加入</span1>` —— 同名标签被拆成两段。
- **复数分支多加 `#`**：原文 `{count, plural, one {Day} other {Days}}` 不显示数字，译文却写成 `other {# 天}`，会重复显示数字。
- **首尾空格丢失**：`' (opens in a new tab)'`（前导空格用于拼接）译成 `'（在新标签页中打开）'`，拼接后会粘连。
- **术语自相矛盾**：Artifact 同时出现 工件/构件/产物/成品/成果/制品 六种译法；Routine 出现 例程/例行程序/常规/日常 四种；credits 出现 积分/信用额度/点数。
